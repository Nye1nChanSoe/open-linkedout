Every layer should either handle an error because it knows what to do
or let it bubble upward.

DO NOT catch errors just to log them and throw again.

current architecture already gives clean place for each decision:
    - repositories execute SQL
    - persistence service owns the transaction
    - orchestrator owns `retry` decisions.

Scraper
    ↓ throws scraping failures

PersistDiscoveredJobsService
    ↓ throws persistence failures

ScrapeAndPersistOrchestratorService (BRAIN)
    ↓ decides retryable vs non-retryable

main.ts
    ↓ handles final unrecoverable failure

NETWORK_ERROR

temporary BROWSER_ERROR
DATABASE_BUSY

Retryable, but NOT here
-----------------------
BROWSER_CLOSED            browser or page died. retrying the same call cannot
                          help, the page is gone and RetryPolicy cannot launch
                          a new one. it must escape to SchedulerWorker, which
                          rebuilds the scheduler, then the task retries.

Non-retryable
-------------
AUTHENTICATION_ERROR
INVALID_SCRAPED_DATA
DATABASE_ERROR            caused by schema mismatch
UNKNOWN_ERROR             by default, anything unrecognised



Retryable Boundries:
initial page.goto()



BROWSER_CLOSED path
-------------------
page.goto()
    v throws "Target page, context or browser has been closed"

toScrapingError
    v BROWSER_CLOSED, retryable

RetryPolicy
    v NOT_RETRYABLE_IN_PLACE, rethrows at once. does not burn the 1h window

Scheduler
    v markRetryWaiting, NOT markFailed

SchedulerWorker
    v isSchedulerStale() -> stop draining, drop the scheduler, rebuild

BrowserSession.getPage()
    v dead page discarded, chromium relaunched, task retries on a live page

WHY: the scheduler and its tasks captured one Page at construction.
a dead browser cannot be healed underneath them. only a rebuild works.
without this, one dead browser marked 65 queued tasks failed in 56ms.



last_error
----------
persist the cause, not only the wrapper message.
describeError() appends it, otherwise every row reads the same line
and says nothing about what actually broke.
