# Layered Architecture

The application is divided into layers.

Each layer owns one responsibility only.

This makes the application easier to maintain,
test and extend later.

---

Scraper
↓
Orchestration
↓
Application Services
↓
Repositories
↓
SQLite

---

Owns browser automation only.

Responsibilities

* open pages
* scroll
* extract data
* pagination
* browser interactions

Should NOT know

* SQLite
* transactions
* retries
* business rules

Mental model

"I know how to scrape LinkedIn."

---

Coordinates the application workflow.

Responsibilities

* scrape page
* persist page
* retry failed operations
* move to next page
* progress reporting
* cancellation

Should NOT know

* SQL
* DOM selectors

Mental model

"I know what happens next."

---

::Application Services

Own business operations.

Responsibilities

* transaction boundaries
* business rules
* coordinate repositories

Example

BEGIN

upsert canonical job

upsert discovery

COMMIT

Mental model

"I know what must succeed together."

---

Own persistence only.

Responsibilities

* prepare SQL statements
* queries
* inserts
* updates
* upserts

Should NOT know

* Playwright
* retries
* application workflow

Mental model

"I know how to talk to SQLite."

Every stage reads from the previous stage,
does its own work,
then writes back to SQLite.

Each stage can later run independently,
be retried independently,
and resume after interruption.
